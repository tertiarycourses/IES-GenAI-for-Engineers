# Lab 1.1 - Onboarding and Tool Access

**Purpose:** Confirm which Microsoft 365 Copilot surfaces are available before later labs depend on them.

**Output:** A completed access record for Copilot Chat, Word, Excel and Agents, including an approved fallback for anything unavailable.

## What you will do

1. Sign in to the provided Microsoft 365 training account.
2. Open Copilot Chat and send a harmless test request.
3. Open Word and check whether Copilot is available.
4. Open Excel with `mock-data.csv` and check whether Copilot can use the file.
5. Open Agents and confirm whether **Create agent** and **Skills (Preview)** are available.
6. Record each surface as Available, Missing or Fallback.
7. Show the record to the trainer before continuing.

## Files used

| File | Use |
|---|---|
| `Lab-Instructions.pdf` | Detailed instructions; start here. |
| `mock-data.csv` | Synthetic file used only for the Excel access check. |

## Detailed steps

1. Open <https://m365.cloud.microsoft/> in a desktop browser.
2. Sign in with the training account. Do not place the username, password or one-time code in any prompt.
3. Open **Copilot Chat**. Enter: `Reply with ACCESS CHECK COMPLETE. Do not analyse any organisational data.`
4. Record whether Chat responds successfully.
5. Open **Word**, create a blank document and look for the Copilot button or prompt area. Do not create a report.
6. Open **Excel**, open `mock-data.csv`, and look for Copilot. If available, ask it to state the number of data rows only. The correct answer is three.
7. Return to Copilot and open **Agents**. Confirm whether Agent Store and **Create agent** are visible.
8. If **Create agent** is visible, open it without creating anything. Record whether **Configure** and **Skills (Preview)** appear.
9. Complete this access record:

| Surface | Record |
|---|---|
| Copilot Chat | Available / Missing / Fallback |
| Word Copilot | Available / Missing / Fallback |
| Excel Copilot | Available / Missing / Fallback |
| Agents | Available / Missing / Fallback |
| Create agent | Available / Missing / Fallback |
| Skills (Preview) | Available / Missing / Fallback |

10. For every Missing item, ask the trainer for the approved fallback and record it. Do not invent a workaround or use a personal account.
11. Show the completed record to the trainer.

## Independent checks

- The CSV contains one header row and three data rows.
- No credential or real engineering information was entered into a prompt.
- Missing access is recorded honestly rather than marked as completed.

## Pass conditions

- Every required surface has a recorded status.
- Every missing surface has a trainer-approved fallback or is clearly marked unresolved.
- The learner can identify where **Create agent**, **Configure** and **Skills (Preview)** would appear.
- The access record contains no credentials.

All supplied records are fictional classroom data.
