# Lab 3.3 Discipline specific specification pack

IES | 20 minutes | LO1, LO2, LO3

All records are fictional training data. They describe no actual facility, person or organisation. Values are teaching assumptions, not approved design criteria. Do not use outputs to operate, maintain or approve real equipment.

## Files

Open Lab-Handout.pdf, prompts.md and the files in mock-data. Each lab is self-contained; earlier outputs may be reused but are not required. Save your work under outputs.

## Procedure

1. Choose a discipline from discipline-options.csv. Use the supplied fictional parameters; do not upload actual employer documents.

2. Create four sections or files from spec-pack-template.md: specification, design checklist, SOP planning outline and troubleshooting guide. State the chosen component and missing domain inputs.

3. Prompt Copilot to draft each component separately so the checklist can be traced to the specification. For non-pump domains, DES-01 is not an applicable design authority; retain relevant domain gaps instead.

4. Add requirement IDs and evidence fields to the checklist. Keep SOP content at planning level unless approved operating procedures are supplied. Troubleshooting recommendations should identify evidence and escalation.

5. Exchange the pack with a neighbour. Score completeness, traceability, uncertainty handling and safe review status from 0-2 each. Correct one issue and submit the four-component pack to the mini challenge.

## Acceptance checks

- All four components are present and consistent.
- Domain-specific gaps are retained and irrelevant pump criteria are excluded.

## If access is unavailable

Use approved paired access or the local source files to prepare a draft and configuration blueprint. Record live agent or permission tests as not executed. Do not use personal accounts to bypass organisational controls.
